# 다중 모델 방법론 비평과 반영 결과

검토일: 2026-11-04.

## 검토 방식과 한계

사용자 요청에 따라 기존 2모델 검토 후, GPT·Claude·Gemini·Grok 네 계열의 **5개 모델로 독립 검토 5회와 동료 검토 5회**를 추가 실행했습니다. 아래 이름은 도구 호출에 지정해 정상 반환된 모델 식별자입니다. 제공 목록 밖 모델이나 특정 계열의 모든 최상위 모델을 사용했다고 주장하지 않습니다.

### 이번 검토: 독립 비평과 실제 상호 반박

| 역할·지적 ID | 1차 호출 모델 | 1차 범위 | 2차에 이 보고서를 비평한 모델 |
|---|---|---|---|
| 온톨로지 의미 O1–O8 | `gpt-6.1-terra` | CQ, 계약 의미, 추론·검증, 독립 정답 | `claude-sonnet-5.5` |
| 실험 타당성 X1–X10 | `claude-sonnet-5.5` | E3 처치·예산, E4 해석, 통계·심판 | `gpt-6.1-sol` |
| 데이터·정답 D1–D8 | `gemini-4-argon` | 실제 형식·좌표·파생 태스크·권리·주석 | `gpt-6.1-terra` |
| 제품·운영 P1-01–06, P2-07–09 | `grok-4.7` | 관리형 경계, API·삭제·ACL·복구·비용 | `gemini-4-argon` |
| 전체 설계 G1-01–09 | `gpt-6.1-sol` | 정형 연결, gate 편향, 승인·범위·가이드 | `grok-4.7` |

1차 에이전트들은 실제 방법론과 기존 검토 문서를 읽고 독립적으로 비평했습니다. 2차는 같은 대화의 후속 턴이 아니라 **새 에이전트 실행**입니다. 각 에이전트에 다른 모델의 ID별 지적·수정안·논쟁점을 전달해 수용/수정/기각을 요구했습니다. 2차 입력은 1차 보고서의 요약이므로 원문 전부를 공유한 공동 토론과는 다릅니다. 다섯 독립 결과를 모으기만 한 것을 상호 검토라고 부르지는 않았습니다.

1차 지적은 O 8건, X 10건, D 8건, P 9건, G 9건으로 총 44개 ID입니다. 같은 문제의 중복, 이미 인지된 미확정 사항, 과도한 권고가 포함돼 있어 **44개의 검증된 결함**을 뜻하지 않습니다. 통합은 투표가 아니라 실험 목적·출처·실행 가능성을 기준으로 했습니다.

### 이전 검토: 보존한 이력

| 역할 | 모델 | 범위 |
|---|---|---|
| 방법론 비평 | GPT-5.3-Codex | 실험 설계, 온톨로지 의미, 데이터·정답·누수·통계 |
| 제품·운영 조사 | Claude Sonnet 5 | 공식 문서·저장소 근거, 관리형 범위, 운영 제약 |
| 통합 | 조정 에이전트 | 두 검토의 충돌·과도한 단정 제거, 실행 계획 반영 |

어느 라운드도 사람 전문가의 승인이나 실험 결과를 대신하지 않습니다. 모델 간 합의는 사실의 증명이 아닙니다. Azure 리소스 배포·성능·권한·복구 동작은 검증하지 않았습니다.

제품 조사에서는 일부 Learn 원문 접속이 DNS 문제로 실패해 검색 수록 내용과 공식 문서 저장소를 사용했습니다. 저장소 기본 브랜치와 공개 문서는 변할 수 있으므로 실행 시 근거 버전을 고정해야 합니다.

이번 연구 에이전트도 GitHub 공식 저장소·코드·검색 색인을 혼용했고, 일부 동료 검토는 원문을 다시 읽지 못했습니다. 보고서 안의 “정확하다”라는 단정도 제품의 현재 지원을 보증하지 않습니다. 상류 기본값·삭제 경로·라이선스·HorizonDB CMK 충돌은 실행 명세에서 고정 버전·권리 확인·수용 시험으로 검증해야 합니다.

## 교차 검토에서 뒤집거나 축소한 권고

**과도한 필수 실험:** 4단계 E3, oracle+추출 두 tier, 모든 제품의 모델 교체, 한국어 고정 문서 수, 심판의 제품 추측률을 모두 필수로 하자는 의견은 축소했습니다. 최소 비교쌍과 필요한 독립 정답을 우선하고 추가 진단은 주장·예산에 따라 승인합니다.

**독립 주석의 착시:** 노드를 미리 합의한 뒤 슬롯만 주석하는 안은 슬롯 평가에는 쓸 수 있지만 개체 발견의 독립 검증이 아닙니다. 부분 gold에서 모든 미기재 관계를 오답으로 보는 점수도 채택하지 않았습니다.

**법적·언어적 단정:** FinanceBench LICENSE 조회 실패를 사용 금지로, Text2KGBench 파생 라이선스를 모든 기업 내부 활용 금지로, 후보 전체를 영어 전용으로 단정한 부분은 채택하지 않았습니다. 실제 자산·이용 방식·태스크별 확인으로 바꿨습니다.

**운영 gate 남용:** HorizonDB에 임의 보존 기준을 강제하거나 예산 승인 전 클러스터를 만들어 확인하는 안, 한 항목의 공란으로 네 대상 전체를 차단하는 안은 채택하지 않았습니다. Preview라는 이유만으로 평가기를 배제하지도 않습니다.

**네이티브의 오해:** 직접 구현 코드가 필요하면 E4에서 제외하자는 안은 기각했습니다. 운영 책임을 드러내는 것이 목적이지, 제품 비교에서 현실적인 통합 비용을 지우는 것이 목적이 아닙니다.

## 검토 의견 중 그대로 채택하지 않은 부분

### Content Understanding을 청킹 도구로만 한정하는 의견

채택하지 않았습니다. 서비스는 사용자 지정 스키마 추출에도 사용할 수 있습니다. 다만 전체 문서 집합의 개체 정합화·업무 온톨로지 관리까지 자동 제공한다고 가정하지 않습니다.

### 모든 고급 추론 태스크를 모든 백엔드에 요구하는 의견

지원하는 의미가 다르므로 일괄 점수화하지 않습니다. OWL 추론이 업무 요구라면 지원 여부 자체를 채택 조건으로 보고, 문서 추출·검색 성능과 분리합니다.

### 사람 검토 수와 soak-test 규모를 즉시 고정하는 의견

검토 에이전트가 제시한 문서·질문 수는 근거 있는 표본 규모가 아니라 예시입니다. 사용자 예산과 pilot의 분산·비용을 보고 결정합니다.

### Preview 연동 실패 시 직접 GQL도 모두 실패로 간주하는 의견

직접 GQL 경로를 사전에 정의한 경우 그 경로는 독립적으로 평가할 수 있습니다. 단, 실패한 NL2GQL 연동을 직접 GQL로 조용히 대체하고 같은 실험의 성공이라고 보고하지 않습니다.

## 구현 전 남은 결정

| 결정 | 필요한 근거 |
|---|---|
| 주 데이터와 보완 데이터 선정 | 원문·주석 확보, 이용 조건, 복잡도·질문 표본 |
| 독립 정답 검토 담당·비용 | 전문가 접근성, 검토 시간, 불일치 조정 방식 |
| 주 지표·최소 의미 차이·표본 규모 | 업무 목적과 pilot 결과 |
| 실험·전체 예산과 조정 한도 | 구독·모델·Fabric 용량·가격·재처리 비용 |
| 허용 지역·Preview·네트워크·복구 조건 | 팀의 실제 운영 정책 |
| 공유 문서 공개 범위 | 팀 내부 자료와 공개 가능한 코드·보고서 분리 |
| 원격 저장소 이름 변경 | `azure-ontology-lab` 사용자 확정. PATCH는 HTTP 403, 별도 저장 OAuth 토큰 없음. 현재 원격명 유지 |

이 비평으로 계획의 허점은 구체화했지만, 실제 측정 전에는 제거됐다고 단정할 수 없습니다. [방법론](methodology.md)의 각 gate에서 증거를 남기고, 막힌 대상과 미충족 조건도 최종 보고서에 포함합니다.
